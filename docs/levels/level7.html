Multi-Domain NAS — Poisson Equation

NAS is applied independently to five different 2-D geometries, all solving the Poisson equation. This tests whether NAS-PINNs generalise across domain shapes — from simple circles to complex 5-petal flower boundaries. Circle achieves L2=0.00014; Flower remains at L2=0.17.

5 geometries Poisson: −∇²u = f Circle L2 = 0.00014 Bayesian · NSGA-II · NSGA-III
Problem Setup

Poisson Equation on 5 Geometries

PDE

−∇²u = f(x, y) on Ω
u = 0 on ∂Ω (Dirichlet BC)

Each domain has a different exact or FDM-reference solution. The PINN is trained using only the PDE loss — no labelled solution data. Accuracy is measured as L2 relative error against the reference.

Why Different Geometries?

Geometry complexity tests the PINN's ability to learn complex boundary shapes. Re-entrant corners (L-Shape) and curved petals (Flower) create challenging boundary conditions and singular features in the solution that standard MLP architectures may struggle to represent.

The Poisson equation −∇²u = f is the canonical test problem for elliptic PDE solvers. By applying NAS independently on five geometries with the same search space, we test whether the architecture preferences found in Level 1 (for the thermal quenching problem) generalise to a different PDE family and different geometric complexity levels. The Dirichlet boundary condition u=0 is easier to enforce than the Robin condition in Levels 1–6, but the boundary geometry itself introduces difficulty — especially for the Flower domain where the boundary oscillates rapidly in polar angle.

Domain complexity follows a clear ordering: Circle (smooth, convex, radially symmetric) is easiest; Square (smooth, corners only) is moderate; L-Shape (re-entrant corner creates a stress-singularity-like feature) is harder; Flower (rapidly oscillating boundary with 5 cusps) is hardest. The Annulus domain failed to converge for all three optimisers (L2 > 1.1), likely due to the challenging inner boundary constraint with the current search space. The 3-orders-of-magnitude gap between Circle (L2=0.00014) and Flower (L2=0.17) demonstrates that boundary geometry — more than PDE type — is the dominant source of PINN difficulty in this comparison.

What are these heatmaps? Each heatmap shows the exact analytical or FDM reference solution u*(x,y) that the PINN must reproduce — this is the target the neural network is trained to match. The Viridis colormap runs from dark purple (low u) to yellow-green (high u). The PINN learns to map (x, y) → u*(x, y) from the PDE loss alone, without seeing these reference values during training. The PINN prediction panels (showing exact vs. predicted vs. L2 error maps) are in the individual domain images below. PINN L2 error quantifies how closely the trained network matches this reference: Circle achieves near-perfect L2 = 0.00014 (essentially the same as the reference), while Flower struggles at L2 = 0.172 because the high-frequency boundary features exceed the representational capacity of standard MLPs. The Annulus is non-convergent (L2 > 1.1) — the inner boundary condition creates a training instability that requires architectural improvements beyond the current NAS search space.

Square: Bayesian only evaluated. Circle, L-Shape, Flower: all three optimisers evaluated. Annulus: all three optimisers non-convergent (L2 > 1.1) — excluded from summary.

Bayesian NAS consistently finds the best architecture across all three fully-converged multi-optimiser domains. The Circle result (L2=0.00014) is exceptionally good — 3 orders of magnitude better than the Flower — confirming that domain topology dominates over optimiser choice for well-behaved geometries. For L-Shape, all three optimisers achieve engineering-level accuracy (L2 < 0.05) with Bayesian leading. The Flower domain is qualitatively different: all three optimisers cluster near L2=0.17–0.18, suggesting a fundamental barrier related to the high-frequency boundary features rather than any optimiser-specific limitation. The Annulus domain failed to converge for all three optimisers.

L2 Error by Domain and Optimiser

The grouped bar chart shows L2 error for each domain (x-axis), with bars coloured by optimiser: Bayesian (blue), NSGA-II (orange), NSGA-III (purple). The logarithmic-like scale reveals the dramatic spread: Circle bars are essentially invisible next to the Flower bars. For most domains Bayesian (blue) is shortest (best L2), consistent with its advantage from using a probabilistic surrogate model. The Flower domain is the exception where all bars reach similar heights — a visual confirmation that the bottleneck is domain complexity, not optimiser quality.

Square Domain — PINN Solution

The Square domain result shows the PINN prediction, analytical reference, and pointwise error for the manufactured solution u*=x²(x−1)²y²(y−1)². Bayesian NAS achieves L2=0.0376 on this domain. The error is highest at the centre of the domain where the solution has its maximum value, but is uniformly small compared to the peak magnitude. This smooth manufactured solution represents a moderate test case for PINN accuracy.

Circle Domain — PINN Solution

The Circle domain result shows the best L2 of the entire study: L2=0.00014 for Bayesian NAS, representing near-perfect recovery of the analytical solution u*=(1−r²)/4. The radial symmetry of both the domain and the solution makes this particularly easy for PINNs — the network only needs to learn a 1D function of r, even though it operates in 2D. The error map is uniformly near-zero throughout the domain, with the very small remaining error concentrated at the outermost boundary points.

L-Shape Domain — PINN Solution

The L-Shape domain result (Bayesian L2=0.0277) demonstrates that NAS-PINNs can handle non-convex domains with re-entrant corners. The PINN correctly predicts zero solution in the excised quadrant [0.5,1]×[0,0.5] while maintaining a smooth solution in the rest of the domain. The largest errors occur near the re-entrant corner at (0.5, 0.5) where the true solution gradient has a singularity-like steepening — a known challenge for all mesh-free methods including PINNs.

Flower Domain — PINN Solution

The Flower domain (Bayesian L2=0.172) is the hardest case in the study. The 5-petal boundary r=1+0.3cos(5θ) creates rapidly oscillating boundary features that a standard MLP architecture struggles to represent accurately. All three optimisers converge to similar L2 values (0.172–0.176), suggesting the bottleneck is the expressiveness of the standard fully-connected MLP search space rather than the NAS optimiser strategy. Architectures with Fourier feature embeddings or periodic activations could potentially improve performance on this geometry.

Takeaways

Key Observations

  • ✓
    NAS generalises across PDE families and geometries Circle L2=0.00014, L-Shape L2=0.028 — three of five geometries solved to engineering accuracy using the same NAS search space as the thermal problem. (Annulus failed to converge; Flower remains at L2=0.17.)
  • ✓
    Smooth convex boundaries are dramatically easier Circle (smooth, convex) achieves 3 orders of magnitude better accuracy than Flower (complex curved boundary). Domain topology dominates over optimiser choice for well-behaved geometries.
  • →
    Flower domain requires architecture-level adaptation L2=0.17 for all three optimisers suggests the MLP search space cannot capture the high-frequency boundary features. Fourier feature networks or periodic activations may be needed.
  • ✓
    Bayesian NAS consistently finds the best architecture Bayesian wins on all four fully-evaluated domains. NSGA-II is competitive on Circle and L-Shape but the probabilistic surrogate model of TPE gives Bayesian a consistent edge.
